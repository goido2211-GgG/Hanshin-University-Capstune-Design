# VoiceAI 자연어 명령

## 명령 해석 모드

`VoiceAgent > Command Routing`의 기본값은 `Prefer Local`이다. 분명한 이동·회전과 연결된 버튼 명령은 로컬에서 처리하고 나머지 표현은 기존 OpenAI Responses API에 전달한다. 음성은 기존 STT를 통과한 뒤 채팅과 같은 경로로 들어온다.

- `Local Only`는 채팅과 로컬 규칙으로 시험한다. 이 모드에서는 API 초기화와 음성 전사를 건너뛴다.
- `Api Interpretation`은 일반 명령을 API가 해석하도록 한다. 즉시 중지와 선택 대상 정정은 같은 로컬 경로를 사용한다.
- Escape와 `멈춰`, `앞으로 가다가 멈춰`는 현재 명령과 남은 단계를 즉시 취소한다. 새 명령도 이전 작업을 대체한다.

해석 API는 JSON 스키마에 맞는 행동을 최대 5개 반환한다. Unity는 인자, 씬 ID, 대상 권한과 접근 거리를 검사한다. 등록된 씬 대상의 이름·별칭·위치, 로봇의 위치와 방향, 직전 대상, 마지막 행동과 결과, 새 명령이 중단한 행동을 전달한다. 화면 영상은 전송하지 않는다. 이전 플레이어 발화를 다음 모델 요청의 기록으로 다시 보내지 않는다. 디버그 패널에는 해석 API의 상태·응답 시간·토큰 수와 음성 전사 시간이 표시된다.

## 행동과 거리

- 상대 이동의 방향은 각 단계 시작 시점의 로봇 정면을 바닥면에 투영해 정한다. `AgentBodyController > Step Length`는 칸·걸음 길이로 기본값 1 Unity unit이다. 미터 입력은 1미터를 1 Unity unit으로 적용한다. 한 단계의 최대 상대 이동은 10 유닛이며 기본 `조금`은 0.5 유닛이다.
- 제자리 회전은 월드 수직축 기준이다. 기본 회전은 90도이며 한 단계에서 최대 180도다. 양수는 오른쪽이다.
- 등록 대상 앞 이동, 조사, 집기·내려놓기, 1초 대기, 한국어 대사 출력 및 순서 있는 행동 조합을 지원한다. `Speak`의 대사는 기존 UI에 표시된다.
- `Interact`는 준비된 `AgentButton`을 누른다. 버튼에 접근 지점과 실제 퍼즐 이벤트를 연결하는 방법은 [맵 버튼 규약](MAP_BUTTONS.md)에 있다.
- 이동은 직선이며 장애물 검사는 `Obstacle Layers`, `Obstacle Radius`, `Obstacle Height`, `Obstacle Bottom Offset`을 사용한다. 벽에 Collider를 붙이고 씬과 로봇 크기에 맞게 캡슐을 조절한다. 경로가 막히면 해당 단계와 남은 단계를 중단한다.
- 시선으로 지칭한 대상은 알 수 없다. 모호한 `저 버튼`은 이름이나 번호를 요청한다. `아니, 옆에 있는 버튼`은 이전 버튼과 3 유닛 이내에 다른 버튼이 하나일 때만 선택을 바꾼다. 두 버튼이 있더라도 대사를 바꾸는 정정 자체는 이동이나 버튼 작동을 실행하지 않는다.

## Unity 시연 5개

1. `Local Only`에서 `앞으로 한 칸 가`, `앞으로 2미터 가`를 차례로 입력한다. 시작 위치를 기록하고 각각 1·2 유닛 이동했는지 확인한다. `Step Length`를 0.5로 바꾸면 칸 명령만 짧아진다.
2. `앞으로 두 칸 가서 오른쪽으로 돌아`로 이동 후 90도 회전을 확인한다. 긴 이동 중 `앞으로 가다가 멈춰` 또는 Escape를 사용해 위치 갱신이 멈추는지 확인한다.
3. 연결된 버튼 하나에 `버튼 앞으로 가서 눌러`를 입력해 접근과 1회 작동을 확인한다. 동일 경로에 Collider를 둔 다음 다시 실행해 장애물 실패와 작동 횟수 유지 여부를 확인한다.
4. 버튼이 두 개일 때 `저 버튼으로 가`가 대상 확인을 요청하는지 본다. `빨간 버튼으로 가` 이후 `이제 그거 눌러`를 실행한다. `아니, 옆에 있는 버튼`으로 유일한 이웃을 선택한 다음 그 대상을 가리켜 누른다.
5. 구성된 API 환경에서 `Api Interpretation`을 선택한다. 채팅 또는 STT로 `두 미터쯤 직진하고 반시계 방향으로 직각만큼 돌아 줘`를 시험하고 응답 시간과 토큰 수를 확인한다. 이어서 API 응답 대기 중 Escape를 눌러 늦게 도착한 응답으로 로봇이 움직이지 않는지 확인한다.

콘솔 회귀 시험은 `Validation/BehaviorTests.csproj`에서 실행한다. 로컬 시험은 UnityShim을 사용하고 API 시험의 전송과 전사는 응답을 모의한다. 실제 모델 해석 품질, Collider 물리와 입력은 Unity에서 별도로 확인한다.

## 대상 확인과 집기

`AgentInteractable`의 표시 이름, ID, GameObject 이름이 대상 식별에 쓰인다. 팀 오브젝트는 `Aliases`에 선수들이 부를 표현을 넣고, 색상으로 찾을 수 있어야 하면 `Color`에 `red` 또는 `빨간색`처럼 실제로 지정한 정보를 입력한다. 색상 표기는 등록된 이름이나 명시적 속성을 근거로 한다. 집기 대상에는 `Allowed Verbs`에 `pick_up`을 넣는다.

`VoiceAI_Integration_Test.unity`에는 `red_box`, `blue_box`, `yellow_box`가 있다. 그 씬에서 `상자 집어`로 재질문을 받은 뒤 `빨간색`을 입력하면 보류한 집기 동작이 이어진다. `빨간상자 집어`, `붉은 상자 집어`, `RedBox 집어`도 시험할 수 있다. 이미 상자를 들고 있다면 시험 전 내려놓는다. `그거 집어`는 이전에 선택한 실제 대상을 사용한다. 재질문 중 Escape 또는 새 행동 명령은 보류를 끝낸다.

문 옆 버튼을 답변으로 선택하려면 실제 버튼에 `문 옆에 있는` 같은 별칭을 등록한다. 같은 근거에 여러 후보가 남으면 응답에 표시된 고유 ID나 구별되는 별칭으로 답한다.
