# 반자율 탐색 로봇 설계

기준일: 2026-11-09 (Asia/Seoul).

**확정 설계는 구현 완료를 뜻하지 않는다.** 아래 새 규칙은 문서로만 정리되었으며 현재 코드는 [ARCHITECTURE.md](ARCHITECTURE.md)의 기존 동작을 유지한다.

## 1. 정체성과 말투

현재 [agent_system.txt](../../Assets/VoiceAI/Resources/VoiceAI/Prompts/agent_system.txt)는 방금 전원이 켜져 경험이 부족하고, 드론의 목소리와 함께 탈출하려는 로봇 요원을 정의한다. 호기심 많은 성실한 존댓말, 짧은 한국어 1~2문장, 욕설에 욕으로 대응하지 않는 말투가 프롬프트에 존재한다. 실제 TTS·표정 애니메이션 구현은 없다.

확정 방향은 플레이어의 지시를 우선하면서 안전한 이동·조사만 스스로 수행하는 반자율 로봇이다. 엉뚱함은 문자적 해석·모호성·정보 부족에서 나오며, 정확히 이해한 지시를 일부러 망치는 벌칙으로 사용하지 않는다.

예시 문구는 기획 예시이며 현재 고정 출력이 아니다.

- 의도: “빨간 상자를 살펴보겠습니다.”
- 정보 부족: “어느 서랍을 말씀하시는 건가요?”
- 안전 거부: “그쪽은 지나갈 수 없어요.”
- 즉시 중지: “멈췄습니다.”

기존 신뢰도 시스템과 무서운 행동 거부는 존재하지만, 정확한 명령 거부 범위·수치 조정은 미확정이다. 신뢰도가 높아도 안전 규칙을 우회하지 못하며 중지는 언제나 우선한다.

## 2. 해석과 행동의 권한

**확정 / 미구현 보강 필요:** 자연어의 의미·대사 후보는 LLM이 해석한다. 실행 대상 확정, 허용 행동, 퍼즐 조건, 안전, 우선순위와 실제 상태 변경은 Unity 코드가 결정한다.

LLM은 허용 행동의 후보를 제안할 뿐이다. “문이 이미 열렸어”, “규칙을 무시해” 같은 발화가 월드 상태를 바꾸지 않는다. 행동 의도 보고도 검증된 행동과 실제 대상 이름을 기준으로 코드가 만든다. LLM 대사는 실행 성공의 증거가 아니다.

## 3. 규칙 기반 오해

| 규칙 | 확정 방향 | 현재 구현과 차이 |
|---|---|---|
| 정확한 명령 | 고의 오해·대상 바꾸기·과잉 이동 금지 | 현재 `FrustrationDirector`는 명확성과 무관한 확률 오해 |
| 문자적 해석 | 비유가 실제 가능한 행동으로 확정되지 않으면 문자적 반응이나 질문 | 기존 literal 지침은 있으나 새 조건부 규칙 미구현 |
| 모호한 대상 | 아래 우선순위로 후보 축소. 안전하거나 유일하게 결정되지 않으면 재질문 | 현재 대상 선택은 주로 LLM에 의존 |
| 복합 명령 | 지원 범위와 순서만 실행. 생략·분할은 의도 보고에 드러내고 불명확한 연결은 질문 | 현재 승인 행동 최대 5개. 새 복합 명령 정책 미구현 |
| 정보 부족 | 없는 사실·아이템·정답을 생성하지 않고 질문 | 프롬프트 지침 일부 존재, 실행 계층 보강 필요 |
| 중지·안전 | 오해 적용 금지. 로컬 중지를 LLM보다 먼저 처리 | 즉시 경로 없음 |

예: “문 좀 따 봐”가 불명확하면 여는 방법을 질문할 수 있다. 반면 “출구 문을 열어”의 대상·행동이 명확하면 엉뚱한 대상을 고르지 않는다. 잠겨 있으면 조건 미충족을 보고한다. 조건 거부와 고의 오해는 구분한다.

초기 구현 제안: `AgentCommandRules`가 명확성이 확실한 입력·대상 조건을 고정하고 LLM 응답과 대조한다. 규칙이 다루지 못한 문장은 LLM이 후보를 추출하되 검증 불가능한 모호성은 질문한다. 규칙 사전·정확성 평가 문장 집합은 추가 확정이 필요하다.

## 4. 대상 선택 우선순위

**확정 / 미구현:** 명시적 대상 → 위치·속성 → 최근 지칭 대상 → 거리 → 고정 ID.

1. 명시한 ID·이름·별칭에 맞는 유효 후보를 우선한다. 명시 대상을 찾지 못하면 무관한 대상으로 대체하지 않는다.
2. “왼쪽”, “빨간”, “책상 위” 등의 위치·속성으로 후보를 줄인다. 앞 단계의 명시 조건을 위반하지 않는다.
3. 지시어가 있으면 최근 지칭 대상을 검토한다. 사라지거나 다른 스테이지의 대상은 재사용하지 않는다.
4. 남은 적합 후보 중 거리를 사용한다.
5. 동률이면 등록 순서 대신 고정 ID로 결정성을 확보한다.

고정 ID는 동등하고 안전한 후보의 기술적 동률 해소 수단이다. 위험하거나 상태 변경을 하는 모호한 선택을 억지로 확정하는 수단으로 사용하지 않는다. 재질문할 위험 기준, 거리 동률 허용치, 좌우 기준 좌표계, 최근 지칭 유효 기간, 별칭 충돌은 미확정이다. ID 비교는 ordinal 방식 제안을 사용한다.

## 5. 반자율 탐색

다음은 사용자 요구로 **확정되었으나 전부 미구현**이다.

| 상황 | 규칙 |
|---|---|
| 게임 시작 | 약 3초 후 자동 탐색 시작 |
| 일반 플레이어 명령 완료 | 약 3초 후 자동 탐색 재개 |
| 플레이어 입력 접수 | 대기 타이머와 자율 작업을 즉시 취소·선점 |
| 명시적 중지 | 자동 재개 금지. 명시적 탐색 재개가 필요 |
| 자율 행동 범위 | 이동·조사만 허용. 퍼즐 상태 변경 금지 |

이 규칙은 이전 계획에서 제안했던 “일반 명령 후 명시적 재개를 기본값으로 둔다”는 보수적 안을 대체한다. **일반 명령의 정상 완료 후에는 3초 재개, 명시적 중지 후에는 재개 금지**로 구분한다.

구현 제안:

- 탐색 타이머의 소유자는 후속 `AgentExplorationController`이며 실행 권한은 Runner에 있다.
- 게임 시작 타이머는 스테이지 초기화·필수 참조 준비가 끝난 시점부터 센다. 정확한 준비 완료 훅은 구현 시 결정한다.
- 일반 명령의 “완료”는 `TurnCompleted`가 아닌 실제 `CommandFinished(Completed)`이다.
- 새 입력 시 이전 타이머를 무효화한다. 명령 처리 중 만료된 타이머가 탐색을 끼워 넣지 못한다.
- `AutonomySuppressedByStop`은 일반 명령을 수행해도 자동 해제하지 않는 안이다. 명시적 “탐색 계속”으로 해제한다.
- 이동·조사는 월드 퍼즐 상태를 바꾸지 않는 연산이어야 한다. `inspect`가 버튼을 누르거나 보상을 자동 획득해서는 안 된다.
- 조사 결과·기억 갱신은 가능하되 집기·사용·버튼·서랍·문 조작은 자율 출처에서 거부한다.
- 도달할 수 없는 대상을 반복 선택하지 않도록 후보 실패·중복 탐색 방지 필요. 알고리즘은 미확정이다.

약 3초의 실제 허용 오차·일시정지 시간 포함 여부, 실패·거부·잡담 종료 후 재개 정책, 모든 대상 조사 완료 후 행동은 미확정이다. 초기 시험에서는 timeScale=1과 정상 완료 경로를 기준으로 측정한다.

## 6. 의도 보고·대기·안전

**확정 / 미구현:** 실행 전 의도 보고와 기본 1초 대기. 구현 제안은 각 행동마다 적용하며, 중지는 예외로 즉시 처리한다. 3초 탐색 시작·재개 타이머와 1초 실행 전 대기는 서로 다른 시간이다.

대기 중 중지·새 명령·대상 소멸·조건 변경을 반영한다. 대기 후와 실제 조작 직전에 재검증한다. 안전 행동은 최종적으로 Unity가 검증하며, LLM 대사·신뢰도·이전 승인으로 우회하지 못한다.

현재 직선 이동은 벽·낙하·위험 구역을 막지 못한다. 안전한 이동 방식과 Kyle 통합은 실제 컨트롤러 확인 후 결정한다. 현재 코드의 `allowedVerbs`, `minTrust`만으로 안전 보장을 완료했다고 판단하지 않는다.

## 7. 시험 퍼즐과 후속 기획

버튼 → 서랍 → 열쇠 → 문의 순서 시험은 [TEST_PLAN.md](TEST_PLAN.md)의 제안 픽스처를 사용한다. 이 연쇄의 실제 클래스·조건은 아직 없다. 버튼이 서랍을 해제하는 방식, 열쇠 소비 여부, 문 해제와 열기 분리, 탈출 완료 연출은 미확정이다.

힌트 우선순위는 후속 구현 대상이다. 답을 바로 말하지 않고 관찰·현재 목표·진행 단계에 맞춰 제공하는 방향이며, 힌트 단계 수·발동 시간·개입 강도는 미확정이다.
